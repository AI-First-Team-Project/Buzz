## 3. 프로젝트 소개(기획의도)

**문제:** 등검은말벌은 벌통 앞에서 돌아오는 꿀벌을 포획한다. 농촌진흥청은 9월 이후 포식 성공률이 높아지고, 말벌류 발생량은 주로 8~10월 늘어난다고 설명한다. 지속적인 출현은 꿀벌의 외부 활동과 먹이·화분 반입을 줄여 벌무리 세력을 약하게 할 수 있다. [농촌진흥청 보도자료, 2026.09.02](https://www.rda.go.kr/board/board.do?mode=view&prgId=day_farmprmninfoEntry&dataNo=100000812776)

**기획 의도:** 양봉장 주변 음원의 말벌 포함 여부를 분석하고, 여러 사업장의 상태·알림·이력을 웹과 모바일에서 한눈에 확인하게 한다.

**현재 시연 흐름:** site1~3 폴더의 WAV/MP3 → 2초 구간 전송 → FastAPI·CNN 판정 → MySQL 저장 → 위험 알림·가상 방어문·화면 표시.

**기대 효과의 범위:** 관리자가 출현 징후를 더 빨리 확인해 보호망·포획장치 점검 등 기존 방제 조치를 판단하는 데 도움을 줄 가능성이 있다. 현장 마이크·실제 개폐기는 연결되지 않았고, 피해 감소 효과는 측정하지 않았다.

## 7. 데이터 전처리

1. **라벨 정의:** 말벌이 포함된 음원은 wasp, 포함되지 않은 음원은 non_wasp. 꿀벌과 말벌이 섞인 소리도 wasp 대상이다.
2. **입력 통일:** WAV/MP3를 모노·24kHz로 읽고 2초 단위로 분할한다. 학습·추론은 같은 구간 규격을 사용한다.
3. **음량·길이 처리:** RMS를 정규화하고 2초보다 짧은 구간의 뒤를 0으로 채운다. 매우 짧은 마지막 구간은 무음 비율이 커질 수 있다.
4. **특징 생성:** CNN은 Mel-Spectrogram을 사용한다. 비교한 전통적 ML 모델에는 MFCC 등의 음향 특징을 사용한다. 파형·FFT·Mel·MFCC는 화면 설명용으로도 계산한다.
5. **평가 누수 방지:** 같은 원본 녹음에서 자른 구간은 같은 그룹으로 묶어 Train/Validation/Test를 나눈다. 데이터 증강은 Train에만 적용한다.

발표 시 전처리 흐름 그림을 권장한다: 원본 음원 → 모노·24kHz → 2초 구간·정규화 → Mel/MFCC → 모델. 실제 자료의 샘플 수·클래스 비율은 확인된 표가 있을 때만 추가한다.

## 8. 모델 비교 및 선정

| 비교 대상 | 입력·접근 | 발표에서 설명할 점 |
|---|---|---|
| RandomForest · LightGBM · XGBoost | MFCC 등 수치 특징 | 전통적 ML 비교군 |
| CNN | Mel-Spectrogram | 현재 FastAPI·Docker가 로드하는 운영 모델 |
| CRNN | Mel-Spectrogram의 시간 변화 | 시계열 구조 비교군 |
| MobileNetV2 | 이미지 형태의 Mel-Spectrogram | 전이학습 구조 비교군 |

**비교 기준:** 말벌 재현율(Wasp Recall), 미탐·오탐, F1, 추론 시간, 모델 크기. **현재 서비스 선택:** CNN. 확률 기준은 서버 설정에 저장되고 판정에 적용된다.

**발표 전 확인 메모:** 저장소의 ai_model/models/training_summary.json은 MobileNetV2를 선택 모델로 기록하지만, 현재 README·Docker 서비스 설정은 CNN을 운영 모델로 사용한다. 두 자료의 목적·실험 시점과 최종 선정 이유를 팀에서 확인하기 전에는 “CNN이 6개 중 정확도 1위” 또는 임시 비교 이미지의 수치를 발표하지 않는다. 비교 그래프를 넣으려면 동일한 데이터 분할·지표의 검증 결과를 다시 확인한다.

## 9. 구현 페이지 소개

| 페이지 | 현재 보이는 핵심 기능 | 캡처 자리 |
|---|---|---|
| 대시보드·모바일 홈 | 전체/개별 사업장 상태, 최근 AI 판정, 알림 | 실제 홈 화면 |
| 모니터링·실시간 분석 | 최신 2초 음원의 파형·FFT·Mel과 말벌 확률 | 실제 분석 화면 |
| 모니터링·감지 이력 | 기간·판정·전체/개별 사업장 필터, 상세 조회 | 실제 이력 화면 |
| 음원 파일 테스트 | 업로드 파일 전체를 2초씩 분석, 구간별 결과·그래프 | 실제 테스트 화면 |
| 사업장·개폐기 | 사업장 조회·등록, 가상 방어문 상태와 수동 제어 | 실제 사업장/문 화면 |
| 설정·보고서 | 말벌 확률 기준 저장, PDF/CSV 보고서 | 실제 설정/보고서 화면 |

**상태 규칙:** Docker 시연 기본값은 말벌 판정 1회에 위험, 비말벌 3회 연속에 정상 복귀다. 열린 가상 문은 위험 전환 시 닫히며, 자동으로 닫힌 문만 정상 복귀 시 열린다. 사용자가 직접 닫은 문은 그대로 둔다.

시뮬레이터는 현장 마이크가 아닌 폴더의 녹음 파일을 사용한다. 최신 자동 분석 그래프는 요청 시 계산하며 모든 자동 분석 구간의 그래프를 DB에 저장하는 것은 아니다. 파일 테스트는 운영 위험 상태와 문을 변경하지 않는다.

## 10. Trouble Shooting

| 겪은 문제 | 원인·확인 | 적용한 조치 |
|---|---|---|
| 일부 2초 음원에서 그래프가 나타났다 사라짐 | 2초 WAV 리샘플링 후 끝에 무음 1샘플이 남아 별도 구간으로 분석됨 | 시뮬레이터에서 해당 1샘플 잔여 구간을 제외하고 단위 테스트로 확인 |
| 위험 상태에서 비말벌 판정이 나왔는데 숫자가 증가함 | 기존 표시는 정상 복귀를 위한 연속 비말벌 횟수를 위험 지속 횟수처럼 보이게 했음 | 화면을 “정상 복귀 진행 X / 3회”로 바꾸고 설정 기준을 서버 판정·화면에 반영 |
| 정상 복귀 후 자동으로 닫힌 문이 계속 닫혀 있음 | 자동 폐쇄와 사용자 수동 폐쇄를 구분하지 않으면 개방 정책을 적용하기 어려움 | 자동 폐쇄 여부를 상태에 기록해 정상 복귀 시 자동 폐쇄된 문만 개방 |
| 사업장 이름·주소에 깨진 한글이 표시됨 | 화면 갱신 후 Docker MySQL에 저장된 잘못된 문자열이 다시 표시됨 | 저장 데이터를 확인·수정하고 출처 데이터를 재점검 |

첫 번째 조치는 **무음 1샘플 문제만** 해결한다. 2초를 조금 넘는 파일의 짧은 마지막 구간에는 무음 패딩이 여전히 많을 수 있으므로 “모든 음원 길이 문제 해결”로 설명하지 않는다.

## 11. 추후 개선 사항

- 실제 양봉장 마이크 음원으로 미탐·오탐과 계절·소음 조건에 따른 성능을 검증한다.
- 2초 미만 잔여 구간의 처리 기준을 정해 무음 패딩이 판정과 그래프에 주는 영향을 줄인다.
- 실제 개폐기를 연결하기 전에는 오작동, 수동 제어, 전원·통신 장애 시 안전 동작을 검증한다.
- 장시간 운영에서 알림 지연·상태 복원·저장 안정성을 점검한다.
- 현장 적용 전후를 비교할 수 있는 평가 계획을 세운다. 실제 피해 감소율이나 경제적 효과는 아직 주장하지 않는다.

**마무리 문장:** “Buzz는 시연 음원을 바탕으로 말벌 포함 여부를 분석하고 위험 정보를 웹·모바일에 연결했습니다. 현장 성능과 피해 예방 효과는 앞으로 검증하겠습니다.”
