# Buzz 중간 발표 자료

> AI 사운드 기반 말벌 감지 및 가상 출입문 제어 시스템
>
> 작성 기준: 2026.09.08 / 팀원 4명
> 기존 프로젝트 일정: 개발 2026.08.28~09.11, 최종 발표 2026.09.15

## 발표자료 생성 가이드

- 아래 내용을 바탕으로 8~10장 분량의 한국어 중간 발표 자료를 제작한다.
- 청중이 이해하기 쉽도록 목표 → 역할 → 일정 → 기술 → 화면 → 진행 상황 순으로 구성한다.
- 정상은 초록색, 위험은 빨간색, 진행 중은 파란색으로 표시한다.
- 각 기능의 상태를 **구현 완료 / 진행 중 / 예정**으로 명확히 구분한다. UI만 구현된 기능은 **UI 구현·실제 연동 예정**으로 표시한다.
- 현재 화면 캡처를 추가할 공간을 배치한다. 캡처가 제공되지 않은 화면을 실제 구현 화면처럼 생성하지 않는다.
- 실제 말벌 감지 정확도, 전체 완성률, 처리 속도 수치는 아직 확정되지 않았으므로 임의로 만들지 않는다.
- 모델 코드는 이진분류로 수정됐지만 서버·앱은 아직 기존 3분류 Mock을 사용한다. 발표자료에서 이 차이를 유지한다.
- 현재 시연 가능한 핵심은 **음원 업로드 → 실제 신호 처리 → 그래프 표시**다. **실제 모델의 말벌 판정 시연은 아직 아니다.**

## 1. 프로젝트 개요 — 목표와 방향

### 프로젝트 소개

**Buzz는 양봉장 주변 소리에서 말벌 포함 여부를 감지하고, 위험 알림과 가상 벌집 출입문 제어로 연결하는 시스템이다.**

양봉장 관리자가 음향 분석 결과와 사업장 상태를 앱에서 확인하고, 탐지 이력과 상세 그래프를 조회할 수 있는 환경을 목표로 한다.

### 최초 구상과 현재 구현 방향

| 항목 | 최초 구상 | 현재 프로젝트 범위 |
|---|---|---|
| 음원 수집 | 양봉장 마이크로 실시간 수집 | 확보한 WAV를 랜덤 재생하고 구간별 전송하는 시연 방식 |
| 분류 목표 | 말벌 / 꿀벌 / 기타 3분류 | 말벌 없음 / 말벌 포함 이진분류 |
| 출입문 제어 | 실제 벌집 입구 개폐기 제어 | 앱 버튼·상태 표시·예시 영상으로 가상 제어 |
| 영상 활용 | 현장 상황 확인 | 정상·위험 상황을 설명하는 사전 확보 영상 |
| 데이터 전달 | 별도 메시지 브로커 검토 | Kafka 없이 FastAPI로 직접 전달 |

**변경 이유:** 제한된 기간과 현장·하드웨어 확보 여건 안에서 음원 입력부터 판정, 알림, 가상 제어까지 이어지는 흐름을 구현하기 위해 범위를 조정했다.

영상은 AI의 입력이 아니라 사용자가 상태를 이해하도록 돕는 표시 자료다. 실제 현장 검증과 실제 장치 제어는 이번 시연 범위에 포함하지 않는다.

### 이진분류 기준

| 라벨 | 의미 | 예시 |
|---|---|---|
| `non_wasp` / 0 | 말벌이 없는 소리 | 꿀벌, 바람, 사람, 기계음 및 이들의 혼합음 |
| `wasp` / 1 | 말벌이 포함된 소리 | 말벌 단독, 말벌+꿀벌, 말벌+환경음 |

말벌이 다른 소리에 섞여 있어도 감지하는 것이 목표다. 말벌의 개체 수를 세거나 미래 출현을 예측하는 모델은 아니다.

### 최종 목표 흐름 — 연동 예정 포함

```text
시연용 WAV 랜덤 선택·재생
    → 재생 시간에 맞춰 2초 구간 전송
    → FastAPI 수신·전처리
    → 선정한 모델로 말벌 포함 여부 추론
    → 서버 상태 갱신·분석 결과 및 이벤트 저장
    → 앱에서 결과 확인
        ├─ 위험 알림
        ├─ 가상 출입문 닫힘 및 상태별 영상 표시
        ├─ 상세 분석 그래프
        └─ 탐지·개폐 이력 조회
```

### 현재 구현된 테스트 흐름

```text
사용자가 MP3/WAV 업로드
    → FastAPI 수신
    → 앞 2초를 24kHz·모노로 전처리
    → 파형·FFT·Mel-Spectrogram·MFCC 계산
    → 수치 JSON 반환
    → 앱의 ‘테스트 음원 분석’ 상세 화면에 표시
```

현재 테스트 화면의 판정과 신뢰도는 파일명 기반 Mock이다. 그래프는 업로드한 음원으로 실제 계산한다.

## 2. 팀원 역할 분담

> 공유된 역할 분담안을 반영했다. 아래 담당 업무가 모두 구현 완료됐다는 의미는 아니다.

| 담당자 | 역할 | 주요 업무 |
|---|---|---|
| 홍준희 | AI 모델 엔지니어 | 오디오 데이터 전처리, 학습 데이터 구성, 분류 모델 설계·학습, 추론 모듈 개발 |
| 강성민 | 데이터 / 인프라 엔지니어 | 말벌·꿀벌 음원 수집, 데이터 저장 구조 설계, DB 설계, 서버 간 통신 구성 |
| 김형준 | 프론트엔드 / UI 엔지니어 | 모바일 대응 UI, 모니터링·AI 분석 결과 페이지, 감지 상태 시각화, UI 동작 테스트, 사용자 시나리오 검증 |
| 오금빈 | MLOps / 운영 엔지니어 | 개발 환경 설정, Git 협업 환경 관리, Jenkins·Docker 환경 구성, CI/CD 파이프라인 구축, 배포·인프라 테스트 |

### 협업 연결

```text
데이터 수집·정리
    → 전처리·학습·모델 선정
    → API 응답 형식 합의·모델 연결
    → 앱 표시·알림·가상 제어
    → 통합 검증·배포
```

랜덤 음원 공급, 실제 모델 API 연결, 알림·개폐 정책, 통합 시연은 관련 담당자 간 공동 작업으로 진행한다.

| 단계 | 작업 묶음 | 주요 산출물·완료 조건 | 현재 상태 |

### 우선순위

1. 원본 음원과 라벨을 정리하고 이진분류 모델을 재학습한다.
2. 실제 모델을 FastAPI에 연결하고 앱의 응답 처리 형식을 변경한다.
3. 사업장 1개 기준으로 랜덤 음원 → 판정 → 알림 → 가상 문 → 이력 흐름을 완성한다.
4. 통합 안정성을 확인하고 사업장 확대·배포 자동화를 진행한다.

**최종 시연 완료 기준:** 학습에 사용하지 않은 음원으로 판정하고, 앱 경고·가상 문 닫힘·DB 이력 저장·당시 그래프 조회까지 이어진다.

### 신호 처리와 모델 추론의 차이

- **신호 처리:** 음원에서 파형·주파수 성분·특징을 계산한다. 학습된 AI 모델 없이도 수행 가능하다.
- **모델 추론:** 계산한 특징을 학습된 모델에 넣어 말벌 포함 여부를 예측한다.
- **현재 테스트 상세 화면:** 신호 처리·그래프는 실제 구현, 모델 판정은 Mock이다.

### 모델 입력과 평가 방향

- CNN·CRNN·MobileNetV2: Mel-Spectrogram을 입력으로 사용한다.
- RandomForest·LightGBM·XGBoost: MFCC 통계 등 수치 특징을 입력으로 사용한다.
- 딥러닝은 2개 softmax 출력으로 `non_wasp / wasp` 확률을 계산한다. 이는 이진분류 방식이다.
- 말벌 확률의 기본 임계값은 0.5이며, 최종 기준은 validation 결과로 조정한다.
- 말벌 재현율, 미탐 수, 오탐 수·비율, Precision/F1과 처리 시간 등을 보고 최종 모델을 선정한다.
- 코드에는 6개 모델의 확률 평균 앙상블 비교도 포함되어 있으나, 최종 서비스 모델은 아직 확정되지 않았다.

## 5. 간이 화면 설명

> 화면 캡처를 붙일 때 **테스트 상세 화면**과 **사업장 분석 탭**을 구분한다. 화면에 보이는 예시 수치·마릿수·기록을 실제 모델 성능이나 실제 탐지 이력으로 설명하지 않는다.

| 화면 | 목적·주요 표시 | 현재 구현 상태 | 앞으로 연결할 기능 |
|---|---|---|---|
| 시작 화면 | 서비스 소개 및 진입 | UI 구현 | 최종 앱 진입 흐름 점검 |
| 홈 | 사업장 정상/위험 상태, 최근 감지 요약 | 예시·로컬 상태 중심 UI | 서버 상태로 갱신, 실제 감지 이벤트 반영 |
| 사업장 | 선택한 사업장의 상태, 영상, 출입문 상태 확인 | UI 및 시연용 상태 표현 | 실제 분석 결과와 가상 문 상태 일치 |
| 분석 탭 | 사업장별 판정·추이·신호 그래프 확인 | 현재 고정 예시 데이터 | 자동 탐지 결과·상세 분석 API 연결 |
| 테스트 | MP3/WAV 선택·업로드, 분석 요청, 결과 요약 | 업로드 API 연동 | 실제 이진분류 모델 판정 표시 |
| 분석 결과 상세 — 테스트 음원 분석 | 파일명, 판정·신뢰도, 파형·FFT·Mel·MFCC | 그래프는 업로드 음원에서 실제 계산, 판정은 Mock | Mock을 실제 모델 확률로 교체 |
| 이력 | 탐지·개폐 기록 및 상세 확인 | 예시·로컬 데이터 중심 UI | DB 조회 및 분석 ID 기반 상세 연결 |
| 가상 개폐기 | 열림/닫힘 상태, 수동 제어 버튼 | 로컬 제어 UI와 서버 제어 API 각각 존재 | API 연결, 자동 닫힘·재개방 정책 적용 |
| 결과 화면 | 사업장별 감지 결과 요약 | 샘플 결과 UI | 실제 이벤트 반영, 중복 화면 역할 정리 |
| 설정 | 알림·진동·자동 폐쇄·기준값 조정 | UI 및 화면 내부 상태 | 서버 설정 저장과 실제 동작 반영 |

### 중간 발표 시연 순서

1. 테스트 화면에서 MP3/WAV 파일을 선택한다.
2. ‘분석 시작’을 눌러 서버에 전송한다.
3. ‘분석 결과 상세 보기’를 연다.
4. ‘테스트 음원 분석’ 화면의 파형·FFT·Mel-Spectrogram·MFCC를 설명한다.
5. 판정·확률은 Mock이며 모델 재학습 후 연결할 예정임을 설명한다.

현재는 파일 전체가 아닌 **앞 2초**를 처리한다. 테스트 업로드는 자동 감지 상태·가상 문·운영 이력에 영향을 주지 않는다.

### 권장 발표 멘트

> “지금 보시는 그래프는 업로드한 실제 음원을 신호 처리한 결과입니다. AI 판정 값은 연동 확인용 임시 결과입니다. 말벌 포함 여부를 판단하는 이진분류 코드는 수정했고, 데이터 정리와 재학습을 거쳐 실제 모델을 연결할 예정입니다.”

## 6. 현재 진행 상황 및 추후 진행 사항

### 현재까지 제작된 부분

| 구분 | 구현 내용 | 현재 범위 |
|---|---|---|
| 방향 정리 | 말벌 포함 여부 이진분류, WAV 기반 시연, 가상 출입문 | 개발 목표 정리 |
| 음원 처리 | 2초·24kHz·모노 처리, RMS 정규화, 파형·FFT·Mel·MFCC 계산 | 업로드 음원으로 실제 동작 |
| 테스트 연결 | 앱 파일 업로드 → FastAPI → 수치 JSON → 상세 그래프 | 신호 처리·시각화 경로 구현 |
| 모델 코드 | 6개 후보의 이진분류 학습·평가·추론, 공통 라벨·임계값 | 코드 수정 완료, 전체 재학습 전 |
| 데이터 분할 코드 | 원본 ID별 분리, 학습/검증/평가 구간 관리 | 동일 원본의 분할 간 중복 방지 |
| 모델 검증 | 이진 판정, 데이터 분리, WAV 추론, 6개 모델 소규모 학습 검사 | 14개 테스트 통과, 실제 탐지 성능 평가는 아님 |
| 서버 기반 | 상태 조회, 자동 분석, 이력 조회, 수동 개폐 API | 모델은 Mock, 기록은 메모리 저장 |
| 앱 화면 | 홈·사업장·분석·테스트·이력·개폐기·설정 | 테스트 그래프 외 다수는 예시·로컬 상태 중심 |

### 이번 이진분류 수정 사항

- `wasp / bee / other`에서 `non_wasp / wasp`로 모델 코드를 변경했다.
- 말벌 단독음과 말벌 포함 혼합음을 같은 양성 라벨로 학습하도록 정의했다.
- 딥러닝과 머신러닝이 같은 파형·분할 기준을 사용하도록 통일했다.
- 말벌 라벨을 1로 정하고 재현율·미탐·오탐 평가를 수정했다.
- 기존 3분류 모델 파일을 정리하고, 새 가중치는 `models/`에 저장하도록 통일했다.
- 수정 범위는 `ai_model` 내부이며, 서버·앱의 분류 형식은 아직 바꾸지 않았다.

### 수집·정리 중인 데이터

- 현재 사용자가 유튜브 등에서 음원을 확보하고 있으며, 말벌음·일반음·혼합음을 정리할 예정이다.
- 실제로 말벌이 들리는 구간을 확인하고 학습용은 2초 이하 WAV로 준비한다.
- `audio/non_wasp/<원본ID>/`, `audio/wasp/<원본ID>/`로 관리한다.
- 같은 영상에서 잘라낸 구간은 같은 원본 ID로 묶고, 시연용 원본은 학습·검증·평가와 별도로 확보한다.
- 합성음은 재료 원본과 파생 음원의 그룹 관계를 함께 관리한다. 혼합음 자동 생성은 아직 구현하지 않았다.
- 파일별 원본 주소, 사용 구간, 출처·이용 조건을 기록한다.

### 앞으로 제작할 부분

| 순서 | 작업 | 완료 시 달라지는 점 |
|---|---|---|
| 1 | 데이터 정리·혼합음 준비 | 말벌 포함 여부 기준의 학습 데이터 확보 |
| 2 | 모델 재학습·평가·선정 | 실제 미탐·오탐을 확인한 모델 확보 |
| 3 | FastAPI 모델 연결·응답 수정 | 파일명 Mock 대신 오디오 특징으로 판정 |
| 4 | 앱 응답 처리 수정 | 말벌 없음/포함 확률과 실제 결과 표시 |
| 5 | 랜덤 음원 공급기 | 시작·정지, 랜덤 재생, 2초 구간 순차 전송 |
| 6 | 가상 개폐기·앱 알림 연결 | 서버 감지 결과로 경고 및 문 닫힘 표시 |
| 7 | DB 저장·조회 | 서버 재시작 후에도 기록 유지, 당시 상세 분석 조회 |
| 8 | 통합 시연·실행환경 정리 | 전체 흐름 검증 및 발표용 실행 구성 |

### 통합 단계에서 정할 동작 규칙

- 말벌 확률 임계값과 연속 감지·미검출에 따른 위험 발생/해제 기준.
- 같은 위험 상황에 대한 알림 중복 방지.
- 위험 상태와 문 상태를 구분하고, 수동 개방 이후 동작 규칙 정의.
- 서버를 상태 기준으로 삼아 홈·사업장·개폐기 화면을 일치시킴.
- 통신 실패·분석 중단을 ‘말벌 없음’과 구분해 표시.
- 우선 앱이 열린 상태의 알림부터 구현하며, 백그라운드 알림은 별도 범위로 판단.

### 발표 마무리 멘트

> “현재는 음원 업로드와 신호 분석 시각화, 이진분류 모델 코드까지 준비했습니다. 다음 단계는 수집 데이터를 이용한 재학습과 실제 모델 연결입니다. 이후 랜덤 음원 공급, 위험 알림, 가상 출입문 제어, DB 이력 저장을 연결해 전체 탐지 흐름을 시연하겠습니다.”
